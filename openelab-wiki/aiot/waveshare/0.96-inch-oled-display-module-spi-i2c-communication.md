# 0.96 inch OLED Display Module, SPI / I2C Communication

{% hint style="info" %}
[**View Waveshare 0.96-inch OLED module on OpenELAB**](https://openelab.io/products/oled-display)

**Family:** 0.96inch OLED Module C/D/E · **Controller:** SSD1315 · **Store options:** `Waveshare-24101` yellow/blue, `Waveshare-24102` white, `Waveshare-24103` blue.
{% endhint %}

## Product overview

The listed C/D/E modules are **128 × 64 SSD1315 displays**. The earlier page described SSD1306 hardware and supplied a generic sketch; use the exact manufacturer's module example instead. C's yellow/blue display has fixed colour regions, not independently selectable RGB pixels. [Official product options](https://www.waveshare.com/0.96inch-oled-module-c.htm?sku=24102), [module wiki](https://www.waveshare.com/wiki/0.96inch_OLED_Module).

## Applications

Use a small text/status display or a compact instrument interface as a first project. Establish an unchanged graphic test before adding fonts, image conversion or a sensor bus. Keep the display update rate and content requirements separate from whether the host can communicate with the controller.

## Specifications

| Item                    | C/D/E family                                    |
| ----------------------- | ----------------------------------------------- |
| Controller / resolution | SSD1315 / 128 × 64 pixels                       |
| Host interface          | 4-wire SPI or hardware-configured I2C           |
| Module dimensions       | 26 × 26 mm                                      |
| Active display area     | 21.74 × 11.18 mm                                |
| Supply                  | 3.3 V or 5 V; I/O high level follows the supply |

Use **3.3 V supply/logic with a Raspberry Pi**. A 5 V supply option does not make 5 V signals safe for a 3.3 V host. [Electrical and connection reference](https://www.waveshare.com/wiki/0.96inch_OLED_Module).

## Hardware and connections

The module defaults to SPI. Changing the interface requires the documented resistor configuration as well as a matching software setting; editing a sketch alone does not change the board. VCC/GND are supply; DIN/CLK are data/clock; CS, DC and RES are control signals. Use the labelled pins rather than the previous page's assumed connector order. [Hardware configuration and schematic](https://www.waveshare.com/wiki/0.96inch_OLED_Module#Hardware_Configuration).

For the manufacturer's **UNO SPI** route, DIN goes to D11, CLK to D13, CS to D10, DC to D7 and RES to D8, plus the documented supply/common ground. Other hosts need their own pin map. [UNO connection table](https://www.waveshare.com/wiki/0.96inch_OLED_Module#Arduino_User_Guide).

## Software and development resources

The [official source archive](https://files.waveshare.com/upload/2/2c/OLED_Module_Code.7z) contains separate model and platform folders. The reviewed Arduino example is `OLED_Module_Code/Arduino/OLED_0in96/OLED_0in96.ino`, with local driver, graphics and configuration files. Keep the directory together. Its `DEV_Config.h` defaults to `USE_SPI_4W=1` and `USE_IIC=0`. The source includes AVR-specific headers; it is not an unchanged ESP32 or Raspberry Pi program.

## Getting started

1. Prepare the C/D/E module, an UNO-compatible board, data cable and the manufacturer's SPI wiring. Disconnect power while making connections.
2. Download and extract the [official archive](https://files.waveshare.com/upload/2/2c/OLED_Module_Code.7z). Open the **OLED\_0in96** Arduino folder, not a neighbouring RGB or 1.3-inch example.
3. Keep the SPI defaults in `DEV_Config.h`. Select the actual UNO board and port in Arduino IDE.
4. Before building, correct two source issues in the reviewed archive: the allocation-error path inside `void setup()` contains `return -1;`, which must be `return;`; and includes written `GUI_paint.h` must match the supplied filename **`GUI_Paint.h`** on a case-sensitive filesystem. Apply the same filename case wherever that header is included.
5. Build before uploading; address any remaining toolchain errors explicitly. Upload only after the wiring and board target agree.

**Expected result from the example:** it cycles through graphics, text and image pages, with diagnostic output at **115200 baud**. The source was inspected; **compilation and hardware execution were not performed**. The fixes above are source corrections, not a claim that the entire archive has passed a build.

## Troubleshooting and FAQs

**No image after powering the module:** OLED has no backlight, so power alone is not a display test. Compare the hardware interface selection, software flags, reset and control wiring before trying another driver.

**I2C scan finds nothing:** confirm that the module has actually been configured for I2C. Check its address-selection circuit and host voltage. Do not apply power to DC where the selected resistor arrangement connects it to ground; use the manufacturer's diagram.

**Compilation fails in setup or cannot find GUI\_paint.h:** check the two archive issues above. A source error is distinct from a wiring fault.

**Wrong colours:** C, D and E are physical colour options. A program cannot turn the monochrome or fixed two-region panel into an RGB display.
