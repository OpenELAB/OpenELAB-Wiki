### Getting started

#### Prerequisites

Confirm source worksheet, actual purchased model and available tools; arrange a safe instructor-supervised workspace. Start with dry-run, paper or screen-based planning wherever the workbook requires unavailable peripherals.

#### First working result

1. Open the worksheet's DobotBlock/Scratch programming interface, create a start event with one speech/display block, then add a loop that repeats a simulated delivery status three times. Run on the stage before enabling any connected robot blocks.
2. Save the project/worksheet and include the model, software version, measured or synthetic input values and any observed fault.
3. Compare the result against the source-defined task, then stop safely before further extension.

**Expected result:** Three displayed delivery status events followed by a stopped program; no robot movement.

#### Extension and assessment

Build the book's Smart Supermarket decision storyboard and explicitly distinguish screen sprites, Magic Box sensors and physical Magician Lite motion. Assessment: provide a labeled workflow, input/output table, one result screenshot and a paragraph describing the hardware prerequisites and failure handling.

### Troubleshooting and FAQs

**What if the first checkpoint fails?** If the Scratch project works but the arm does not respond, check hardware selection, USB/COM, deployed block type and whether real robot control was actually intended; an animated sprite is not a motion-control test.

**Can this lesson run on a bare DOBOT Magician Lite?** Only its screen/paper or included-tool parts can. The lesson's required items are enumerated above; check the selected bundle and manual before physical extensions.

**What should be done after a motion or electrical fault?** Stop with the verified physical control, power down as prescribed, document controller alarm/status, and obtain qualified instruction before retrying. Do not bypass a safety mechanism.
